## 数据迁移实测

中文文件来自 `选题4 数据.zip` 内的 `Dataset.rar`，解包后按原始内容放入 `data/raw/movie_reviews_zh/`。聚合审计在 `data/processed/movie_reviews_zh/dataset_audit.json`，其中含原始文件指纹、标签分布和重复统计。附件 ZIP 的 SHA-256 为 `b6d44ff46d8b41dbc5eb7d705afd5f83e15211685ba6404c2cbb0749dd4e9717`。

| 分区 | 有效样本 | 空行 | 原始标签 0 | 原始标签 1 | 集内多余重复行 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Train | 19,998 | 0 | 9,999 | 9,999 | 2 |
| Validation | 5,629 | 2 | 2,817 | 2,812 | 0 |
| Test | 369 | 3 | 182 | 187 | 0 |

- 空白归一化的完全匹配发现 2 种文本同时出现在 train 与 validation，对应 2 条训练行，同名文本的标签一致。Train/Test 与 Validation/Test 均为 0。Stage 0 建议从派生训练集排除这 2 行，并移除剩余 2 条同标签重复行。按此政策派生 train 为 19,994 条，两个评估分区沿用原文件，加载时跳过空行。原始文件当前未改动。
- 从 train 按原始标签各抽查 8 条短评，语义指向 **0 为正向、1 为负向**。包内只有数据和向量文件。Stage 0 应对照课程说明，或记录扩大的独立人工抽样结果后冻结这份映射。二分类内部把语义正类映射到目标 1，输出同时回写原始标签。
- 中文 train 按空格切分的长度 P50/P90/P95/P99 为 43/59/62/68，最大 679。当前长度候选为 256，原始训练集仅 1 条超过。冻结时记录派生 train 的复核结果，并让同数据集的神经实验共用该长度。
- `wiki_word2vec_50.bin` 的文件头为 426,677 词、50 维，大小 89,008,408 字节，SHA-256 为 `6a3dc817b85269ea15c18fab1b023456bb70f1531eefeac1e15c9a6f38453071`。向量加载、实际词数校验和训练词表覆盖率在 Stage 1–2 完成。
- GoEmotions 官方文件尚未导入。Stage 0 需核对官方标签顺序、43,410 / 5,426 / 5,427 条及三分区哈希，保留 ID 和文本重合审计。英文 Word2Vec 仅从 GoEmotions train 文本做 50d 无监督训练。

## 一个总任务，六个自动执行阶段

以下是审阅通过后的一次执行。总任务从最早未通过阶段继续，依赖该阶段产物的工作在验收成功后接着跑。进度记录写明阶段、代码版本、执行命令、检查结果、Run ID 及失败原因。

### Stage 0 · 审计与冻结

1. 记录迁移后的基线版本、diff、两份数据配置及批次配置的指纹。安装或确认运行依赖，固定实验使用的 Python 和库版本。
2. 导入 GoEmotions 官方简化版，复验下载来源、各分区数量、28 标签、ID 重合、文本重复和哈希。完成中文语义标签、去重和 50d 数据来源核对。
3. 生成两套数据的版本化 manifest、派生分区 ID 清单、排除记录和输入长度选择。Stage 0 可以读取 test 做来源和数据质量检查，输出聚合统计。此阶段不产生模型侧测试分数。
4. 冻结两个数据版本、标签编码、训练选择指标与 14 个矩阵键。后续参数只能写入新的配置版本和 Run 记录，正式测试始终绑定同一份最终冻结清单。

**出关条件**为来源明确，哈希可回算，清洗可重放，标签和分区规则有书面记录。中文初审已通过，双数据冻结待完成。

### Stage 1 · 统一基础设施

1. 配置解析读取两个 dataset YAML 和一份 suite YAML。检查引用、模型枚举、任务类型、标签数量、Embedding 配置及指标，展开唯一的 14 个组合，写入 resolved config。
2. 任务适配器提供三件事，即样本与标签编码、train-only 特征构建、训练与验证分区加载。GoEmotions 用 28 维 multi-hot。中文用单目标 BCE，并保留原始标签反向映射。词表、TF-IDF、英文 Word2Vec 只从 train 获取信息。
3. 统一 SVM 与神经 Runner 的入口、数据审计引用及输出。SVM 保留已有 E1 逻辑，添加中文二分类。PyTorch 路径提供训练、验证、最佳权重重载和失败记录。两条路径统一生成 Run manifest、配置快照和评分类型。
4. 实现二分类和多标签统一的指标入口。GoEmotions 以 validation Micro-F1 选择全局阈值及最佳 epoch。中文首选 validation Macro-F1。平分时优先默认阈值距离较小的候选，仍平分取较小阈值，最佳 epoch 平分时保留更早者。正式规则随配置冻结，现有独立 E1 保留已有阈值选择行为。
5. 校验 Windows 虚拟环境和 GPU。当前 `nvidia-smi` 识别到 RTX 4070 Ti SUPER、16,376 MiB、驱动 610.88。当前 Python 3.12.13 的虚拟环境可运行旧 E1 和测试，缺 PyYAML、PyTorch、Gensim。安装后先验证 CUDA 可用、张量计算和 Word2Vec 本地加载。

**出关条件**为配置错误可定位，训练在没有 test 路径时能跑，两个任务的合成数据走通特征、指标、产物保存和重载。正式测试入口的冻结门禁用构造数据验证。

### Stage 2 · 七种模型配置与合成冒烟

| 配置 | 实现与验收重点 |
| --- | --- |
| E1 | 两任务的 TF-IDF + LinearSVC。多标签 OvR 和中文二分类分别验证分数形状、阈值与重载。 |
| E2 | 随机可训练 50d Embedding 的 TextCNN，卷积核 3/4/5、各 100 filters。测试短句、PAD 和有效窗口。 |
| E3-RNN / E3-LSTM / E3-BiLSTM | 共用词表、批处理和训练循环，处理长度与 padding。先用 hidden size 128，记录参数量及双向合并方式。 |
| E5-TUNE / E5-FROZEN | 与 E2 使用同一 TextCNN、数据、训练配置和非 Embedding 初始化。分别测试词嵌入更新及冻结权重不变，记录预训练覆盖率。 |

两个任务均通过全部 7 个配置的合成训练。每组验证一轮 fit 或 epoch、有限 loss、正确目标输出、checkpoint 重载后预测一致和训练期间 test 不可访问。E5-RANDOM 只引用 E2。

### Stage 3 · 14 组正式训练

1. 按 suite 生成完整队列，E1 用 CPU，神经模型使用一张 GPU 串行。首轮 14 个尝试固定 seed 42。以 12 epoch 上限、patience 3、有效 batch 64、学习率 0.001 和 grad clip 1.0 起跑，锁定每个实际运行值。
2. 每次尝试在进程开始时保留 Run 目录，记录代码、设备、数据与配置版本。每个 epoch 留训练曲线和 validation 指标，结束时归档最佳权重、阈值和预测。E1 记录单次 fit 的时间与验证结果。
3. OOM 先检查微批次和梯度累积，保持有效 batch 并记录调整。重试分配新 Run ID，关联原失败记录。其余组合可继续处理。断点恢复要验证来源、优化器状态及配置，队列重启后成功项直接复用。
4. 只用 validation 选权重和阈值，并核对不同模型在同数据集使用相同分区。Stage 3 的结果表标明失败、重试次数和最终候选。测试数据文件路径和测试指标均不进入训练逻辑。

**出关条件**为 14 个矩阵键各有可审阅的成功 Run。若某个配置仍失败，保留完整错误与诊断，不生成完整冻结清单。

### Stage 4 · 独立复核、冻结与最终测试

1. 用独立复核步骤检查矩阵覆盖、选择指标、阈值规则和 checkpoint 重载。复核只看验证结果、配置、测试门禁和数据版本。先核对完成记录，再签出冻结清单。
2. 在 `artifacts/suites/<suite_execution_id>/final_runs.yaml` 固定 14 项的 Run ID、任务/模型 ID、checkpoint/配置/阈值哈希、预处理和 split manifest 指纹，以及评估器版本。清单写入后禁止覆盖。test 文件哈希取自 Stage 0。
3. 正式评估入口先验证清单完整性、每项产物哈希及运行锁，再打开对应的测试文件。用冻结的权重与阈值计算该任务测试指标和逐样本预测。
4. 成功结果通过排他状态与原子发布保存。中断可继续同一冻结批次中未成功的项，保留失败证据。清单或输入漂移时停止该批评估。

**出关条件**为两套正式 test 各 7 项评估完整，指标和逐样本输出可从冻结清单反查，终测期间没有改动配置、模型和阈值。

### Stage 5 · 报告与交付验收

1. 从正式产物生成两张模型对照表、两个数据集各自的 E5 三条件比较、训练曲线和失败记录。GoEmotions 附逐标签 P/R/F1、类别分布和主要错误。中文附混淆矩阵、语义正类指标及置信区间，使用相同的测试样本比较模型。
2. 用同一输入生成课程报告草稿、复现手册和验收证据。每个表格条目都能定位到 Run、配置版本、冻结项和指标文件。汇总脚本能对同一批冻结结果重建产物。
3. 在独立环境验证安装、全套测试、冻结产物重放和报告生成。正式测试结束后才启动前端设计，展示使用真实的两任务预测与已验证结果。
